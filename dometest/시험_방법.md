# 둥근 언덕 시험판

`DomeTest.rbxlx` 하나를 Roblox Studio에서 열고 **Play(F5)** 하세요. 지형은 Play 때 만들어집니다. 편집 화면이 비어 있는 것은 정상입니다. 원래 WILDHOLD와는 별도 파일입니다.

## 걸어보는 순서

1. 꼭대기 모닥불 옆에서 시작하는지 확인합니다. WASD·점프·카메라는 Roblox 기본 조작입니다.
2. 30 → 60 → 90 → 120 표지를 따라 내려가며 모닥불을 돌아보세요. 가까운 3인칭과 1인칭을 각각 시험하세요. 기본 카메라를 멀리 줌아웃하면 언덕 너머가 보여 효과가 약해집니다.
3. 120 표지 부근에서 꼭대기를 바라보고 기다리세요. 괴물은 **반대쪽(북쪽)** 가장자리 138 stud에서 기지 14 stud까지 약 25초에 걸쳐 접근하고 되돌아갑니다. 한 바퀴 약 50초입니다. 꼭대기에서 기다리는 것보다 이 위치가 머리부터 나타나는지 보기 좋습니다.
4. 기지로 돌아갈 때 불꽃과 말뚝이 언덕 뒤에서 올라오는지 확인하세요.
5. 오른쪽 위 **밤으로 / 낮으로** 버튼으로 비교합니다. 밤의 조명은 모닥불 중심입니다. 눈은 네온 재질입니다. 버튼은 자신의 화면만 바꿉니다.
6. 숲 둘레를 걸어보고 맵 밖으로 빠지지 않는지 확인합니다.

### 체크리스트

- [ ] 스폰 후 땅을 뚫고 떨어지지 않는다.
- [ ] 오르내릴 때 심한 걸림이나 미끄러짐이 없다.
- [ ] 모닥불·말뚝·표지·나무가 떠 있지 않다.
- [ ] 괴물이 2회 이상 왕복하며 땅 아래로 잠기거나 떠다니지 않는다.
- [ ] 남쪽 표지에서 북쪽을 보면 괴물이 머리부터 나타난다.
- [ ] 밤에 모닥불이 밝고, 낮으로 되돌릴 수 있다.
- [ ] 기본 카메라의 가까운 시점에서 원하는 지평선 느낌이 난다.
- [ ] View → Output에 빨간 오류가 없다.

## 숫자 바꾸기

Studio에서 **Stop**을 누르고 Explorer의 `ReplicatedStorage → Shared → Dome`을 엽니다. 맨 위 `C` 표의 숫자를 바꾼 뒤 다시 Play 하세요. Play 중 바꾸면 종료할 때 사라질 수 있습니다. 저장은 Ctrl+S입니다.

| 설정 | 시작값 | 뜻 |
|---|---:|---|
| SphereRadius | 600 | 공 반지름. 작을수록 굽음이 강함 |
| PlayRadius | 150 | 숲이 시작되는 거리 |
| ForestWidth | 20 | 가장자리 숲 폭 |
| TopY | 40 | 꼭대기 높이 |
| SoilDepth | 12 | 표면 아래 흙 두께 |
| Embed | 0.6 | 물건을 지면에 묻는 깊이 |
| TreeSpacing | 9 | 나무 간격 |
| MonsterSpeed | 5 | 괴물의 수평 이동 속도 |
| MonsterNear | 14 | 기지 접근 거리 |
| MonsterEdgeInset | 12 | 놀이 범위 끝에서 안쪽으로 들어올 거리 |
| MarkerDistances | 30,60,90,120 | 표지 거리 |

먼저 **600 / 150**, 다음 **500 / 150**, 마지막 **700 / 150**을 비교하세요. 각각 가장자리 경사는 약 14.5도 / 17.5도 / 12.4도입니다. 꼭대기와 가장자리 높이 차는 약 19.1 / 23.0 / 16.3 stud입니다. 이 수치는 구면 수식 기준이며 Terrain 복셀 표면에는 작은 오차가 있습니다.

`PlayRadius + ForestWidth < SphereRadius`를 유지하세요. 나무 간격은 6~12, SoilDepth는 8 이상을 권장합니다. 거대한 구 전체가 아니라 표면 아래 12 stud만 생성합니다. 충돌과 시각적 곡면은 Roblox의 4 stud Terrain 복셀을 사용하므로 완벽한 수학적 구면은 아닙니다.

## 숲 키트 사용(선택)

기본 제공 파일은 파트 나무로 바로 실행됩니다. FBX 파일을 XML에 직접 넣는 것으로는 Roblox 메시가 만들어지지 않습니다.

Studio의 3D Importer로 저장소 `wildhold/assets/env/EnvModels.fbx`를 가져옵니다. `Spruce1`, `Spruce2`처럼 `Spruce`로 시작하는 나무 Model 또는 MeshPart 이름을 유지하고 `ReplicatedStorage.EnvModels` 안에 넣으세요. 다시 Play 하면 해당 나무를 사용합니다. 바위·양치식물은 선택하지 않습니다. Studio에서 임포트한 뒤 저장한 파일은 Python 재빌드 전에 별도로 보관하세요. 재빌드는 소스만 포장하므로 수동 임포트한 메시를 포함하지 않습니다.

## 소스에서 재빌드

저장소 루트에서 Python 3로 실행합니다.

```sh
python dometest/tools/build_place.py
python dometest/tests/check_place.py
luau dometest/tests/geometry.luau
```

소스 설정은 `dometest/src/shared/Dome.lua`입니다. XML 포장은 기존 `wildhold/tools/build_place.py`를 읽기 전용으로 재사용합니다. 실행할 때 기존 게임 스크립트를 불러오지는 않습니다.

## 검사 범위와 한계

헤드리스에서는 실제 공용 Luau 모듈의 구면 높이·얕은 흙층·괴물 왕복 경로 20,000개 시점을 검사합니다. 생성 XML의 소스 일치와 기본 카메라/중력 유지도 검사합니다. 기존 `wildhold/tests`와 마찬가지로 헤드리스 검사는 실제 Roblox 엔진을 대신하지 않습니다.

**Studio 실행, 실제 Terrain 충돌·레이캐스트, 물건 접지, FBX 임포트, 낮/밤 렌더링, 캐릭터 보행, 괴물의 시각적인 접지·지평선 효과는 아직 확인하지 않았습니다.** 위 체크리스트로 직접 확인해야 합니다. 기지를 숨기는 정도는 카메라 높이와 관찰 위치에 따라 달라지며, 원하는 느낌을 보장하는 완성 맵이 아니라 비교용 시험판입니다.

사용한 API 참고: [Terrain](https://create.roblox.com/docs/reference/engine/classes/Terrain), [Model](https://create.roblox.com/docs/reference/engine/classes/Model).
