# 로블록스 벤치마킹 — 총 군대 만들기 / 골프 공을 치세요

스크린샷 두 장(게임 상세 페이지)에서 읽은 것과, 거기서 나온 "바이브코딩으로 비슷하게 만들기" 계획.
**확인한 것**(스크린샷에 보이는 숫자·문구)과 **추론한 것**을 구분해서 적는다.

---

## 확인된 사실

| | 총 군대 만들기 | 골프 공을 치세요 |
|---|---|---|
| 개발자 | Weapon Williamson (인증 배지) | Tiny Loop |
| 좋아요 비율 | **98%** | **88%** |
| 동시 접속 | 약 2,500명 | 약 1,200명 |
| 연령 수위 | 약함 (총·좀비) | 최소 |
| 설명 핵심 | 총 구매 → 좀비 방어 → 코인 → 더 좋은 총. **자동 발사, 오프라인에도 방어** | 공 치기 → 거리 → 파워 업그레이드 → 새 클럽 해금 → 거리 기록 |
| 상점 | 스크린샷에 안 보임 | **바로 노출**. 근육 팔 아이콘(파워 부스트로 보임) 여러 개 |

> 동시 접속 1~2천은 상위권은 아니지만, 이 장르 게임은 개발비가 거의 안 들어서 이 정도면 충분히 남는 장사다.

---

## 두 게임의 공통 구조

둘 다 장르 껍데기만 다르고 뼈대는 같은 **"숫자가 커지는 게임"(incremental / simulator)** 이다.

```
행동 1번 (클릭 or 자동)  →  보상 (코인)  →  업그레이드 구매  →  행동 효율 ↑  →  (반복)
                                                         └→  다음 단계 해금 (총 / 클럽)
```

| 요소 | 총 군대 | 골프 |
|---|---|---|
| 핵심 행동 | 총 배치 (이후 자동 사격) | 공 치기 (타이밍 / 클릭) |
| 보상 | 좀비 처치 코인 | 비거리 비례 코인 |
| 업그레이드 | 더 비싼 총, 총 개수 | 파워 스탯, 클럽 |
| 수집 | 총 종류 (AK, 저격총, 로켓, 미니건…) | 클럽 종류 |
| 목표 | "가장 부유해지기" | 거리 기록 |
| 방치 요소 | **있음** (오프라인 방어) | 없어 보임 |

### 왜 잘 되나 (추론)

1. **썸네일 한 장으로 게임 설명이 끝난다.** 좀비 수백 마리 vs 총 한 줄 / 거대한 "HIT THE BALL!". 클릭하기 전에 뭘 하는 게임인지 안다.
2. **조작이 사실상 0.** 모바일 어린이 유저가 튜토리얼 없이 바로 한다.
3. **첫 업그레이드가 10~30초 안에 온다.** 이 장르의 생명선.
4. **방치 보상(총 군대)** → 다음 날 다시 들어올 이유. 98%라는 높은 평점과 무관하지 않다고 본다.
5. **에셋이 거의 없다.** 블록 캐릭터 + 무료 총 모델 + 바닥 타일. 1인 / 소규모 팀이 빨리 찍어낼 수 있는 구조.

### 골프가 88%인 이유 (추론)

상점이 상세 페이지 첫 화면에 바로 뜨고, 상품이 전부 "파워" 계열이다. 돈 내면 거리가 늘어나는 구조는
**과금 유저와 무과금 유저의 체감 격차가 크다** → 싫어요가 붙는다. 총 군대는 방치형이라 무과금도
"자고 일어나면 늘어 있음"을 느낀다.

→ 만들 때 **과금은 "시간 단축"으로, 무과금도 언젠가 도달 가능하게** 설계한다.

## 바이브코딩 난이도

| | 골프형 | 총 군대형 |
|---|---|---|
| 난이도 | ★★☆☆☆ | ★★★★☆ |
| 핵심 기술 | 포물선 연출 + 저장 | **수백 마리 좀비 이동 + 타겟팅 + 성능** |
| 함정 | 거의 없음 | 좀비마다 `Humanoid` 쓰면 서버 렉으로 터짐 |
| 첫 플레이 가능 버전 | 주말 1~2일 | 1~2주 |

**→ 골프형으로 먼저 하나 완성해서 출시까지 해보고, 그다음 방치 디펜스로 가는 걸 추천.**
첫 게임의 목표는 대박이 아니라 "기획 → 출시 → 데이터 보기" 한 바퀴를 도는 것.

## 기술 설계 (로블록스에서 실제로 필요한 것)

### 공통

- **저장**: `DataStoreService` 직접 쓰지 말고 커뮤니티 표준인 **ProfileStore**(구 ProfileService) 사용. 데이터 날아가는 버그가 이 장르 최대 악평 원인.
- **리더보드**: `leaderstats` 폴더(머리 위 / 탭 목록) + `OrderedDataStore`(전체 랭킹 보드).
- **서버 권위**: 코인 계산은 **무조건 서버에서**. 클라이언트가 "나 10000m 쳤어"를 보내면 그대로 해킹당한다. 클라이언트는 "쳤다"는 신호만 보낸다.
- **수익화**
  - 게임패스(1회 구매): 코인 2배, 자동 치기 / 자동 수집, VIP
  - 개발자 상품(반복 구매): 코인 팩, 일시 부스트
  - `MarketplaceService.ProcessReceipt` 는 영수증 처리 실패 시 재시도되므로 **중복 지급 방지** 필수
- **방치 보상**: 퇴장 시 `os.time()` 저장 → 입장 시 `min(경과초, 상한) × 초당수입`. 상한(예: 8시간) 안 걸면 밸런스 붕괴.

### 골프형

- 공 비행은 물리 엔진에 맡기지 말 것. **거리는 서버가 공식으로 계산**하고(`거리 = 파워 × 클럽배율 × 타이밍보너스`), 클라이언트는 그 거리에 맞춰 포물선만 그린다.
- 타이밍 게이지(움직이는 바에서 초록 구간 맞추기) 하나만 넣어도 "실력" 요소가 생겨서 과금 불만이 줄어든다.
- 맵은 일직선 페어웨이 + 거리 표지판(100m, 1km, 10km…). 표지판마다 배경 테마를 바꾸면 "더 멀리 가보고 싶다"가 생긴다.

### 총 군대형

- 좀비는 `Humanoid` 없는 단순 `Model`로, 서버는 **위치·체력 숫자만** 10Hz 정도로 갱신. 걷는 애니메이션·총알 궤적은 클라이언트가 그림.
- 총은 매 틱 "사거리 안 가장 앞선 좀비" 하나만 타겟. 전체 탐색이 무거우면 레인(줄) 단위로 나눠서 찾는다.
- 배치는 스크린샷처럼 **바닥 타일 그리드 + 반투명 미리보기(고스트)**. 그리드 스냅이라 구현이 쉽다.
- 웨이브 사이 휴식 시간에 상점을 열게 하면 자연스럽게 구매 동선이 생긴다.

## 차별화 — 그대로 베끼면 안 되는 이유와 대안

이름·썸네일·모델을 그대로 가져오면 신고로 내려간다. **가져올 건 루프 구조뿐**이다.
그리고 똑같은 게임은 먼저 낸 쪽이 이긴다. 한 가지는 바꾼다.

| 아이디어 | 설명 |
|---|---|
| 대상 바꾸기 | 공 대신 친구 / 펫 / 변기 / 수박 날리기. 썸네일 웃김이 곧 클릭률 |
| 환생(Rebirth) | 일정 거리 도달 시 초기화 대신 영구 배율. 이 장르 장기 플레이의 핵심인데 두 게임 설명엔 안 보임 |
| 펫 | 뽑기형 펫이 파워 보너스. 수익화 + 수집욕 |
| 둘 섞기 | 골프 공을 쳐서 몰려오는 좀비를 맞추기 → 맞춘 좀비 수 = 코인 |
| 협동 | 서버 전체 합산 거리 목표 → 달성 시 전원 보상. 친구 초대 이유 |

## 바이브코딩 순서 (AI에게 줄 프롬프트)

**도구**: Roblox Studio 기본 Assistant로도 되지만, 코드가 길어지면 **Rojo + VS Code + Claude Code** 조합이 낫다
(스크립트를 파일로 관리 → git 버전관리 가능). 로블록스 공식 Studio MCP 서버를 연결하면 AI가 Studio를 직접 조작할 수도 있다.

한 번에 다 시키지 말고 **한 단계씩, 매 단계 Studio에서 플레이 테스트** 후 다음으로 간다.

1. **뼈대**
   > 로블록스 골프 비거리 게임을 만들 거야. ServerScriptService에 서버 스크립트, StarterPlayerScripts에 클라이언트 스크립트로 나눠줘. 우선 플레이어가 클릭하면 RemoteEvent로 서버에 알리고, 서버가 `거리 = 파워 × 10` 으로 계산해서 leaderstats의 Coins와 BestDistance를 올리게 해줘. 클라이언트가 거리 값을 보내면 안 되고, 서버가 계산해야 해.

2. **연출**
   > 서버가 계산한 거리를 클라이언트에 돌려주면, 공이 그 거리만큼 포물선으로 날아가는 연출을 TweenService나 매 프레임 CFrame으로 만들어줘. 카메라가 공을 따라가고, 떨어지면 거리 숫자가 크게 뜨게.

3. **업그레이드 상점**
   > 파워 업그레이드 상점 UI를 만들어줘. 가격은 `기본가 × 1.15^레벨`. 구매 검증은 서버에서. 클럽 5종(배율 1, 2, 5, 12, 30)도 거리 조건 달성 시 해금되게.

4. **저장**
   > ProfileStore로 Coins, PowerLevel, BestDistance, 해금한 클럽 목록을 저장해줘. 서버 종료(BindToClose) 때도 저장되게.

5. **타이밍 게이지**
   > 클릭 전에 좌우로 움직이는 게이지를 띄우고, 가운데 초록 구간에서 멈추면 타이밍 보너스 ×2. 판정은 서버가 할 수 있게 클릭 시각만 보내줘.

6. **환생 + 리더보드**
   > BestDistance가 일정 값을 넘으면 Rebirth 버튼 활성화. 누르면 Coins와 PowerLevel 초기화, 영구 배율 +50%. OrderedDataStore로 전체 BestDistance 상위 10명 보드를 로비에 세워줘.

7. **수익화**
   > 게임패스 '코인 2배'와 개발자 상품 '코인 1000개'를 MarketplaceService로 처리해줘. ProcessReceipt는 PurchaseId로 중복 지급을 막아줘. (ID는 내가 나중에 채울게)

8. **출시 전 체크**
   > 이 코드에서 클라이언트가 조작해서 코인을 부풀릴 수 있는 지점이 있는지 검토해줘.

## 손절 / 판단 기준

출시 후 볼 숫자는 Creator Hub 애널리틱스의 세 개면 충분하다.

| 지표 | 뜻 | 낮으면 |
|---|---|---|
| D1 리텐션 | 다음 날 돌아온 비율 | 방치 보상·일일 보상 추가 |
| 평균 세션 길이 | 한 번에 얼마나 노는지 | 첫 업그레이드까지 시간 단축 |
| 썸네일 클릭률 | 노출 대비 클릭 | 썸네일·아이콘 교체 (게임 수정보다 먼저) |

썸네일 / 아이콘은 A/B 테스트가 된다. 이 장르는 **게임보다 썸네일이 더 중요**할 때가 많다.
