## 0. 제보하신 버그 — 해적이 다시 안 나오던 문제

> "해적 튀어 올라서 잡고 계속 이어가면 끝날 때까지 해적이 또 안 나와.
>  갑자기 초기화되고 한 번 더 하게 되는데 그래도 해적이 안 나와."

### 원인

위험한 자리는 **통을 채울 때 딱 한 번만** 뽑았습니다. 4인 테이블은 그게 한 자리였습니다.
그리고 잡기에 성공하면 통을 다시 채우지 않았습니다 (그게 Phase 5 의 의도였습니다).

문제는 **그 한 자리에 이미 칼이 꽂혀 있었다**는 것입니다.
칼이 꽂힌 자리는 다시 고를 수 없으니, 그 순간부터 통에 남은 자리는 전부 안전해집니다.

```
칼 16자루 · 위험한 자리 1곳
  └ 그 자리를 밟는다 → 해적 등장 → 잡는다 → 살아남음
      └ 그 자리는 이제 "칼이 꽂힌 자리"
          └ 남은 15자리는 전부 안전  ← 여기서부터 아무 일도 안 일어남
              └ 15자리를 다 뽑아야 통이 새로 채워짐  ← 이게 "갑자기 초기화"로 보였습니다
```

"초기화 뒤에도 안 나온다"고 느끼신 것도 같은 이유입니다. 새로 채운 통에도 위험한 자리는
다시 하나뿐이라, 그 하나를 밟기 전까지는 또 한참을 아무 일 없이 뽑기만 하게 됩니다.

### 고친 방법 — 세 겹으로 막았습니다

1. **잡으면 해적이 하나 더 숨습니다. 아직 칼이 안 꽂힌 자리에.** (요청하신 그대로)
   잡는 데 성공한 그 순간, 서버가 빈 자리 중 하나를 골라 새 해적을 숨깁니다.
   통을 새로 채우지 않으니 판은 그대로 이어지고, 긴장은 끊기지 않습니다.
2. **턴을 시작할 때마다 마릿수를 세고 모자라면 채웁니다.**
   탈락·이탈·타이밍 문제 등 어떤 경로로 해적이 사라져도 다음 턴에 반드시 복구됩니다.
   이 한 줄이 마지막 방어선입니다.
3. **해적 수가 좌석 수를 따라갑니다.** 6인 테이블은 두 마리입니다.

```lua
-- GameConfig.Catch
ArmOnCatch = 1,          -- 잡으면 빈 자리에 이만큼 새로 숨긴다
MinFreeSlotsToArm = 1,   -- 남은 자리가 이보다 적으면 숨기지 않는다
                         -- (마지막 한 칸이 무조건 해적이면 그건 게임이 아니라 처형입니다)
```

### 확인한 것 ✅

| 검사 | 결과 |
|---|---|
| 잡으면 해적이 하나 새로 숨는다 | ✅ |
| 새 해적은 "아직 칼이 안 꽂힌" 자리에 숨는다 | ✅ |
| 이미 칼이 꽂힌 그 자리에 다시 숨지 않는다 | ✅ |
| 잡기에 성공해도 통을 새로 채우지 않는다 (판이 이어진다) | ✅ |
| **잡은 뒤에도 해적을 다시 만난다** | ✅ |
| 해적을 일부러 전부 지워도 다음 턴에 복구된다 | ✅ |
| 6인 테이블은 잡은 뒤에도 두 마리를 유지한다 | ✅ |

**여전히 지키는 것**: 어느 자리가 위험한지는 서버 메모리에만 있습니다.
검사로 확인했습니다 — 해적이 숨은 슬롯과 그냥 빈 슬롯은 Attribute 로 구분되지 않습니다. ✅
밖으로 나가는 것은 "몇 마리인지"까지입니다.

## 2. 카메라 — 해적이 안 보이던 문제

> "해적이 나올 때 카메라 앵글이 너무 확대되고 해적 쪽으로 확대가 안 되어서 해적이 안 보여"

### 원인

카메라는 **통 뚜껑**을 기준으로 2.3스터드까지 파고들며 화각을 94도로 벌렸습니다.
그런데 해적은 **통 중심에서 5.2스터드 위, 카메라보다 앞쪽**에 서 있었습니다.

계산해 보니 이랬습니다.

```
카메라 눈  : 통 중심 + 2.05 높이, 나를 향해 2.3스터드
해적 중심  : 통 중심 + 5.2 높이,  나를 향해 1.5스터드
→ 해적이 카메라보다 0.8스터드 뒤, 3.1스터드 위
→ 카메라와 해적 사이 거리 3.2스터드 (해적 몸 안에 들어가 있는 셈)
→ 아랫몸이 화면 밖 148% 지점, 머리끝이 91% 지점
```

화면에는 해적이 아니라 **외투 천이 가득** 찼습니다. 화각만 벌어져서 통 표면만 커 보였고요.

### 고친 방법

1. **해적이 실제로 서는 지점을 직접 계산해서 그 지점을 봅니다.**
   `pirate()` 가 해적을 세우는 식과 카메라가 바라보는 식이 이제 같은 상수를 씁니다.
   (`SCARE.GhostRise` · `SCARE.GhostLunge` — 둘 중 하나만 고치면 안 되도록 주석을 달았습니다)
2. **해적의 실제 키를 재서, 화면에 다 들어오는 최소 거리까지만 다가갑니다.**
   스킨마다 키가 달라도 알아서 맞춥니다.
3. **화각을 94도 → 82도로 줄였습니다.** 확대가 아니라 접근으로 놀래킵니다.
4. 파고드는 동안에는 통 뚜껑을, 들이닥치는 순간 시선이 해적으로 넘어갑니다.

### 확인한 것 ✅ — 실제 `closeShot` 코드를 그대로 떼어 와 계산했습니다

| 해적 키 | 머리끝 | 발끝 | 판정 |
|---|---|---|---|
| 5.0 | 59% | 53% | ✅ |
| 6.5 | 72% | 64% | ✅ |
| **7.2 (기본)** | **77%** | **68%** | ✅ |
| 8.0 | 83% | 70% | ✅ |
| 9.5 | 91% | 74% | ✅ |
| 11.0 | 92% | 76% | ✅ |
| *옛 계산 (7.2)* | *91%* | ***148%*** | ❌ 잘림 |

(100% 를 넘으면 화면 밖입니다)

- 카메라가 해적에게 7.6스터드까지만 다가갑니다 (옛날에는 3.2) ✅
- 통에서 가장 멀어질 때도 12.4스터드 — 검은 무대 벽(29) 안쪽 ✅
- 잡기 창이 열리는 순간 해적이 화면 한가운데에서 **3.7도** 안에 있습니다 ✅
- 테이블 아래로 내려가지 않습니다 ✅

해적도 오래 남습니다. 예전에는 1.3초 만에 사라져서 클로즈업이 끝나기도 전에 없었습니다.

## 3. 통 스킨이 겹칠 때 — 누구 것을 보여줄까

> "만약 통 스킨을 적용한 사람이 둘 다 있으면 레벨 높은 사람 것이 적용되도록 하자.
>  레벨 말고 다른 게 좋으려나? 이건 네가 판단해줘"

### 먼저, 구조를 바꿨습니다

Phase 5 까지 통 스킨은 **각자 화면에서만** 바뀌었습니다. 그래서 애초에 겹칠 일이 없었습니다.
겹치는 문제를 말씀하신 것은 **통 스킨이 모두에게 보이기를 바라신다**는 뜻으로 읽었습니다.
그래서 서버가 테이블마다 통 스킨 하나를 골라 직접 칠합니다. 이제 같은 테이블 모두가 같은 통을 봅니다.

### 판단 — 레벨만으로 정하지 않았습니다

레벨만 보면 이런 일이 생깁니다.

> 전설 통을 방금 산 새 플레이어가, 기본 참나무 통을 쓰는 100레벨 고인물에게 **항상 집니다.**
> 그러면 통 스킨을 살 이유가 사라집니다. 상점이 죽습니다.

그래서 **희귀도를 1순위로, 레벨을 2순위로** 두었습니다.

| 순위 | 기준 | 이유 |
|---|---|---|
| 1 | **스킨 희귀도** (전설 > 영웅 > 희귀 > 기본) | 어렵게 얻은 통이 이긴다. 상점이 의미를 갖는다 |
| 2 | **레벨** | 같은 등급이면 오래 한 사람이 이긴다 ← **요청하신 규칙** |
| 3 | **현재 연승** | 지금 잘 나가는 사람이 이긴다 |
| 4 | **먼저 앉은 순서** | 남은 동점은 여기서 항상 똑같이 갈린다 (통이 깜빡이지 않게) |

현황판에 `통: 심연의 통 (○○ 님)` 이라고 누구 것인지 뜹니다.
내 것이 안 보여도 왜 안 보이는지 알 수 있습니다.

레벨은 `승수 × 40 + 판수 × 12` 로 쌓이고 뒤로 갈수록 천천히 오릅니다. 참가만 해도 오릅니다.

**희귀도보다 레벨을 위에 두고 싶으시면** `GameConfig.barrelSkinScore` 의 자릿수 두 개를
서로 바꾸면 됩니다. 한 줄입니다. 확인한 것 ✅ (6가지 상황 전부)

## 6. 스킨이 밋밋하던 문제

> "스킨이 지금 멋있지 않은데 좀 더 이펙트랑 디자인 화려하게 할 순 없어?"

Phase 5 까지 스킨은 **색과 재질만** 바뀌었습니다. 그래서 전설 스킨도 색 다른 나무통이었습니다.
`SkinFX` 모듈을 새로 만들어 진짜 이펙트를 붙였습니다.

| 효과 | 모습 |
|---|---|
| `emit` | 은은하게 피어오르는 입자 |
| `spark` | 사방으로 튀는 반짝임 |
| `trail` | 칼이 움직일 때 남는 꼬리 |
| `halo` | 바닥에 깔려 숨 쉬는 고리 |
| `pulse` | 밝기가 천천히 커졌다 작아짐 |
| `smoke` | 느리고 큰 연기 (잿불 · 드럼통) |
| `bubbles` | 위로 올라가는 물방울 (심해 · 크라켄) |
| `coins` | 튀어 오르는 금화 (보물 상자) |

붙는 곳: 전시대 모형 · 게임 안의 통 · 통에서 튀어나오는 해적 · 꽂힌 칼.

**새 스킨도 넣었습니다** — 화산의 통 · 유빙의 통 · 공허의 왕.
받침대 테두리 색이 등급 색으로 바뀝니다 (기본 회색 / 희귀 파랑 / 영웅 보라 / 전설 금색).

성능은 인색하게 잡았습니다. 숨 쉬는 애니메이션은 매 프레임 도는 코드 대신
`TweenService` 무한 반복을 씁니다. 테이블 10개가 동시에 돌아도 버티게 만들었습니다. 🔍

## 7. 간판의 쓸데없는 설명

> "간판에 칼 스킨 밑에 있는 쓸데없는 설명들 없애줘. 통 스킨 밑에나 해적 스킨 밑에도"

지웠습니다.

- ~~"내가 꽂는 칼은 모두에게 보인다"~~ → 간판에는 **`칼 스킨`** 만

## 8. 맵 — 항구와 해적선

> "이 맵을 좀 더 화려하게 꾸며줘. 배같이"

`MapBuilder` 를 새로 만들었습니다. 파트 **약 700개**를 서버가 숫자로 지어 올립니다.

### 큰 해적선 (부두 오른쪽, 건널판으로 이어져 있습니다)

선체는 길이 방향으로 자른 단면 22장을 늘어놓아 만듭니다. 뱃머리와 고물로 갈수록 좁아집니다.

- **대포 8문** (양옆 포문에서 포신이 나옵니다) · 닻 · 뱃머리 사장 · 선수상
- 갑판 위 짐 상자와 등불

### 그 밖에

- **바다** — 세 겹으로 깔아 깊이감을 냈습니다. 부두 테두리에 흰 포말
- **작은 어선 두 척** — 부두 왼쪽
- **등대** — 멀리 바위섬 위. 붉은/흰 띠 탑에 불빛
- **부둣가** — 짐 상자 26더미 · 통 22개 · 밧줄 더미 · 갈매기 7마리
- **통로 등불** — 좌우로 매달린 랜턴 26개

### 성능 (Phase 6 점검표)

- 장식은 전부 `CanCollide` · `CanTouch` · `CanQuery` **끔** — 물리와 레이캐스트가 건드리지 않습니다
- 그림자 **끔** — 모바일에서 그림자 캐스터 수가 프레임을 가장 많이 먹습니다

- 짐은 통로(가운데 ±14스터드)와 테이블 주변을 피해서 놓습니다
- 접속이 늦어지지 않도록 첫 프레임 뒤에 세웁니다

기존 로비는 **한 파트도 건드리지 않았습니다.** 전부 새 폴더에 새로 세웁니다. 🔍

## 9. 빈 자리로 가는 화살표

> "어떤 사람이 앉아 있고 다른 플레이어를 기다리고 있으면,
>  안 앉아 있는 사람한테 제일 가까운 자리로 네비게이션 같이 화살표가 밑에 뜨게"

발밑에서 목표 자리 쪽으로 **화살표 6개가 흘러갑니다.** 목표 자리 위에는 작은 표지가 뜹니다.

```
빈 자리
검은 닻 · 2/4명 · 34스터드
```

- 내가 이미 앉아 있으면 뜨지 않습니다
- **아무도 안 앉은 테이블만 있으면 뜨지 않습니다** (기다리는 사람이 없으니 급할 게 없습니다)
- 카운트다운 중인 테이블을 먼저 봅니다 — 거기가 제일 급합니다.
  그때는 화살표가 청록색으로 바뀌고 `곧 시작! 빈 자리` 로 바뀝니다
- 9스터드 안에 들어오면 조용히 사라집니다

전부 내 화면에서만 그립니다. 서버는 이 기능을 모릅니다. 🔍

## 10. 연승 표시

> "연승기록도 플레이어 위에 숫자로 띄워줘. 불 표시 안에"

머리 위에 🔥 안에 숫자가 뜹니다. 불꽃이 천천히 숨 쉬고 좌우로 일렁입니다.

| 연승 | 불꽃 색 |
|---|---|
| 2~3 | 주황 |
| 4~6 | 붉은 |
| 7~9 | 보라 |
| 10+ | 청록 |

- **2연승부터** 보입니다 (1연승은 그냥 한 판 이긴 것이라 시끄럽기만 합니다)
- 연승이 올라가면 한 번 튀어오릅니다
- 90스터드 밖에서는 사라집니다
- 랭킹판에도 `🔥 5` 로 함께 뜹니다
- 기본 순위표(Tab 키)에 `연승` 항목이 생깁니다

**연승은 탈락하거나 게임 중에 스스로 나가면 끊깁니다.** (나가서 연승을 지키는 짓 방지)
우승 보상도 연승 1회당 +35 코인씩 늘어납니다 (6연승까지).

## 14. 파일 구조와 빌드

```
game/                                Luau 소스 (여기를 고칩니다)
  ReplicatedStorage/CursedBarrel/Shared/   GameConfig · TableConfig · Utility · SkinFX
  ServerScriptService/CursedBarrel/
    Main.server.lua                        서버 진입점
    Services/                              12개 서비스
  StarterPlayer/StarterPlayerScripts/Controllers/   6개 클라이언트 컨트롤러

place/CursedBarrel_Phase8.rbxl       ← Studio 에서 여실 파일
tools/build_place.py                 game/ 소스를 .rbxl 에 심습니다
tools/rbxconv/                       .rbxl ↔ .rbxlx 변환기 (Rust)
tests/                               115개 자동 검사
docs/                                이 문서
```

```bash
# 소스를 고친 뒤 플레이스 다시 만들기
cargo build --release --manifest-path tools/rbxconv/Cargo.toml   # 처음 한 번만
python3 tools/build_place.py place/CursedBarrel_Phase5.rbxl place/CursedBarrel_Phase8.rbxl

# 검사 돌리기  (luau 는 github.com/luau-lang/luau 릴리스에서 받습니다)
LUAU=/경로/luau ./tests/run.sh
```

`build_place.py` 는 `game/` 트리를 그대로 읽어 스크립트를 넣고 바꿉니다.
파일 이름이 종류를 정합니다 — `Name.lua` 는 ModuleScript, `Name.server.lua` 는 Script,
`Name.client.lua` 는 LocalScript 입니다. Studio 에서 손으로 옮길 일이 없습니다.
