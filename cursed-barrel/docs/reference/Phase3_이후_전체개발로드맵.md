# 저주받은 통 — Phase 3 이후 전체 개발 로드맵

## 현재 파일에 이미 구현된 것

`CursedBarrel_Phase3.rbxl`을 직접 읽어 확인한 결과입니다.

- 서버 스크립트와 클라이언트 스크립트 12개
- `SelectSlot` RemoteEvent 1개
- 4인 테이블 4개: 테이블당 좌석 4개, 칼 슬롯 16개
- 2인 테이블 2개: 테이블당 좌석 2개, 칼 슬롯 10개
- 전체 칼 슬롯 84개와 관련 태그/Attributes
- 카운트다운과 서버 턴 순서
- PC·모바일용 슬롯 선택 UI와 ProximityPrompt
- 서버 측 차례/테이블/거리/슬롯/연타 검증
- 위험 슬롯을 서버 메모리에만 보관
- 안전 선택, 위험 선택, 탈락, 통 재충전
- 마지막 생존자 승리와 5초 후 초기화
- 자동 시간 초과 선택
- 테이블 6개의 독립 진행
- 로비 조명과 게임 중 개인 화면 조명 전환
- 서버 랭킹, leaderstats, 랭킹판 1개
- 선택형 DataStore 코드

내장 스크립트 12개의 Luau 문법 검사는 모두 통과했습니다. 실제 Roblox 엔진에서의 캐릭터 물리, UI, 네트워크 동작은 Studio 테스트가 필요합니다.

## 1. 지금 가장 먼저 할 일 — Phase 3.5 안정화

이 단계가 끝나기 전에는 상점이나 스킨을 만들지 않는 편이 좋습니다.

### 실제 Studio 플레이 테스트

- 혼자 앉기 → 5초 카운트다운 → 첫 턴 → 슬롯 선택
- 안전 슬롯 선택 후 다음 턴으로 넘어가는지 확인
- 위험 슬롯 선택 후 탈락·자리 이탈·통 재충전 확인
- 혼자 위험 슬롯을 뽑았을 때 무승부 처리와 초기화 확인
- 2명 테스트에서 마지막 생존자 승리 확인
- 4명 테스트에서 턴 순서, 연속 탈락, 승리 확인
- 한 사람이 게임 중 나가기, Reset Character, 네트워크 끊김
- 카운트다운 중 이탈과 재참가
- 게임 시작 후 빈 의자 강제 참가 차단
- 다른 테이블의 슬롯 선택 요청 거부
- 같은 슬롯 연속 클릭과 RemoteEvent 연타 방어
- 턴 종료와 슬롯 선택이 같은 순간에 발생하는 경쟁 상태
- 테이블 두 개 이상 동시 진행
- 라운드 종료 직전 플레이어 퇴장
- Output 창의 서버·클라이언트 빨간 오류 확인

### 출시 규칙 확정

현재 `Standard4`와 `Duo2` 모두 `MinPlayers = 1`이라 혼자서도 게임이 시작됩니다. 개발 테스트에는 편하지만 공개 서버에서는 파티 게임의 의미가 약해집니다.

- 테스트 중: `MinPlayers = 1`
- 출시 권장: `MinPlayers = 2`
- 4인 테이블을 3명 이상으로 시작할지 결정
- 턴 시간 7초가 적절한지 결정
- 탈락할 때마다 통을 완전히 재충전할지 결정
- 시간 초과 시 자동 선택 또는 턴 패스 중 하나로 확정
- 4인·2인 테이블의 보상 차이 결정

### 랭킹 저장 수정

현재 `GameConfig.Ranking.UseDataStore = false`라 서버가 종료되면 기록이 사라집니다. DataStore를 켜기 전에 저장 코드를 보강해야 합니다.

- `UseDataStore = true` 전환
- `SetAsync` 대신 충돌에 강한 `UpdateAsync` 사용
- 승자뿐 아니라 모든 참가자의 판수 저장
- PlayerRemoving과 BindToClose에서 저장
- 저장 실패 재시도와 요청 예산 관리
- 데이터 스키마 버전과 기본값 추가
- Studio API 접근을 켠 별도 테스트 Place에서 검증
- OrderedDataStore 기반 전 서버 랭킹이 필요한지 결정

현재 코드에서는 승자의 기록만 즉시 저장하고 패자의 증가한 판수는 영구 저장하지 않으므로, 그대로 DataStore를 켜는 것은 권장하지 않습니다.

## 2. Phase 4 — 게임 연출과 손맛

핵심 규칙이 작동한 뒤 가장 먼저 체감 품질을 높이는 단계입니다.

### 통과 칼 연출

- 플레이어 손에서 칼이 통으로 날아가는 애니메이션
- 칼 꽂히는 짧은 충격과 통 흔들림
- 안전 슬롯의 작은 반응
- 위험 슬롯 선택 전 0.2~0.5초 긴장 지연
- 통 뚜껑 열림과 저주받은 해적·유령·괴물 등장
- 탈락 플레이어 넉백 또는 짧은 래그돌
- 과도하지 않은 화면 흔들림
- 위험·승리 VFX와 파티클
- 마지막 두 명일 때 긴장 연출 강화

### 카메라

- 앉을 때 테이블이 잘 보이는 카메라 위치
- 내 차례에 통과 슬롯으로 부드럽게 줌
- 다른 플레이어 선택을 관전하기 좋은 구도
- 위험 발생 시 짧은 컷인
- 탈락하면 로비·관전 카메라로 복귀
- 카메라가 벽이나 캐릭터 몸에 끼지 않도록 검사

### 사운드

- 로비 BGM과 게임 중 긴장 BGM 분리
- 카운트다운 소리
- 칼 선택·삽입·금속·나무 충격음
- 통 덜컹임과 위험 직전 사운드
- 탈락 효과음
- 승리 팡파르
- UI 클릭·거절·남은 시간 경고음
- 음량 설정과 음악/효과음 분리

에셋 ID는 직접 확인한 소유·사용 가능한 음원만 사용해야 합니다.

## 3. Phase 5 — UX, 튜토리얼, 관전

### 처음 접속한 사용자

- 스폰 후 5~10초 안에 빈 테이블을 찾을 수 있는 동선
- 첫 게임에만 보이는 짧은 단계 안내
- `의자에 앉기 → 내 차례 기다리기 → 슬롯 선택` 세 단계 설명
- PC, 모바일, 게임패드 조작 안내
- 긴 설명문 대신 화살표·Highlight·색 변화 활용

### 플레이 중 정보

- 현재 차례 플레이어를 캐릭터·좌석·현황판에서 동시에 강조
- 사용된 슬롯과 선택 가능한 슬롯을 색상 외 모양으로도 구분
- 남은 턴 시간 3초 이하 경고
- 안전·탈락 결과를 모든 참가자가 볼 수 있게 표시
- 승자 이름과 보상 표시
- 서버가 거절한 요청의 짧고 명확한 안내

### 탈락과 관전

- 탈락 후 테이블 주변 관전 모드
- 다음 판 재참가 버튼 또는 빈 의자로 이동 안내
- 관전자가 슬롯을 누르지 못하도록 처리
- 게임 중 재접속한 사용자를 참가자에 복구할지 로비로 보낼지 결정
- 장시간 자리 비움과 AFK 처리

### 접근성

- 색약 사용자를 위해 아이콘·문양 병행
- 화면 흔들림 끄기
- 번쩍이는 효과 줄이기
- UI 크기와 모바일 안전 영역 확인
- 한국어·영어 최소 2개 언어 구조 준비

## 4. Phase 6 — 아트와 맵 완성

현재 맵과 모델은 기능 검증용 Part 기반 구조입니다.

### 핵심 오브젝트 직접 완성

- 시그니처 저주받은 통
- 칼과 칼 손잡이 스킨
- 플레이어 의자
- 원형 테이블
- 통에서 나오는 독창적인 괴물
- 승리 왕관·오라·포즈

### 해적 선술집 환경

- 입구와 중앙 게임 홀
- 2인·4인 테이블 구역 구분
- 상점과 랭킹 공간
- 선술집 바와 바다 창문
- 랜턴, 밧줄, 상자, 해골, 보물 장식
- 테이블 주변은 슬롯과 빈 의자가 잘 보이도록 정돈
- 외곽에 장식 밀도를 높여 테마 강화

무료 모델을 사용할 때는 장식용 시각 에셋만 선택하고 Script, LocalScript, ModuleScript, RemoteEvent, 외부 `require`를 모두 검사해야 합니다.

### 성능

- 모바일 저사양 기기에서 FPS와 메모리 확인
- 불필요한 투명 파트, 그림자, 파티클 감소
- 장식 모델 폴리곤 수와 텍스처 크기 제한
- 충돌이 필요 없는 장식의 CanCollide/CanTouch/CanQuery 비활성화
- CollisionGroup으로 캐릭터와 장식 충돌 정리
- StreamingEnabled 사용 여부와 테이블 Atomic 스트리밍 확인
- 동시에 여러 테이블에서 VFX가 발생할 때 성능 확인

## 7. 출시 전 필수 QA

- PC 키보드·마우스
- iPhone·iPad
- Android 저사양·고사양
- 게임패드·콘솔

- 한국어·영어 UI 길이

### 서버와 보안

- RemoteEvent에 잘못된 Model, 슬롯 번호, 문자열, nil 전송
- 매우 먼 거리에서 선택 요청

- 차례가 아닌 플레이어 요청
- 이미 사용된 슬롯 요청
- 초당 수십 회 요청
- 플레이어가 선택 직전에 죽거나 나가는 상황

- 위험 슬롯 수 변경

1. Phase 3 실제 멀티플레이 테스트와 버그 수정

3. 탈락·승리 카메라, 애니메이션, 사운드, VFX
4. 튜토리얼과 관전 흐름

6. DataStore 저장 구조 완성
7. 맵과 핵심 모델 완성
8. 성능·보안·장시간 서버 테스트
9. 코인, 인벤토리, 상점, 스킨

지금 당장 다음 개발 목표는 **Phase 3.5 테스트·버그 수정**과 **Phase 4 연출**입니다. 이 두 단계가 끝나면 친구에게 보여 줄 수 있는 첫 번째 완성형 버전이 됩니다.
