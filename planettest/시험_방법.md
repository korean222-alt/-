# PlanetTest — 작은 행성 걷기 2차 시험판

2차 수정: 실제 Studio 로그의 `Modules is not a valid member of PlayerScripts` 오류를 고쳤습니다. 조작 파일과 공용 모듈이 늦게 도착해도 기다린 뒤 시작합니다. 외형 다운로드 대기도 최대 5초로 제한했습니다. 반지름은 220 → 160으로 줄여 곡률을 더 쉽게 비교할 수 있게 했습니다. 기존 파일을 열어 둔 Studio 탭은 닫고 새 파일을 다시 열어야 수정 코드가 적용됩니다.

`PlanetTest.rbxlx` 하나를 Roblox Studio에서 열고 **Play(F5)** 하세요. 행성과 물건은 Play 때 생성됩니다. 편집 화면이 비어 있는 것은 정상입니다. **Run만 누르면 플레이어가 없으므로 Play로 시작합니다.**

기존 `wildhold/`, `WILDHOLD.rbxlx`, `dometest/`와 독립된 파일입니다. 펫·전투·자원·건설·저장은 없습니다. 추가 화면 버튼은 낮/밤 하나이며, 휴대폰에는 Roblox 기본 이동·점프 조작이 표시됩니다.

이것은 **두 번째 동작 시험판**입니다. 기존 버전의 실제 Studio 오류 로그를 확인하고 수정했습니다. 수정본은 계산과 모의 엔진 검사를 했지만 Studio를 직접 실행해 보지는 못했습니다. 캐릭터의 실제 충돌, 카메라 느낌, 휴대폰 실기기, 2인 복제는 확인이 남아 있습니다.

## 1. 시작과 기본 조작

- PC: **WASD** 이동, **Space** 점프, **마우스 오른쪽 버튼을 누른 채 움직이기**로 카메라 회전, 휠로 거리 조절.
- 휴대폰: **왼쪽 기본 조이스틱** 이동, **기본 점프 버튼**, **오른쪽 빈 화면 드래그**로 카메라 회전. 이동·점프·낮/밤 버튼을 누르는 터치는 카메라 회전에 사용하지 않습니다.
- 카메라는 3인칭입니다. 확대 범위는 5~32 stud이며 1인칭·Shift Lock·VR은 이 시험 범위에 없습니다.
- 아바타 모양과 R6/R15 리그는 그대로 사용하고, 걷기·점프 애니메이션은 행성 이동 상태에 맞춰 재생합니다.
- 멈췄을 때 계속 미끄러지거나 땅을 뚫으면 아래 문제 보고 양식에 적어 주세요. 메뉴의 **Reset Character**로 재시작할 수 있습니다.

## 2. 걷기·점프·한 바퀴

1. 모닥불 뒤에서 시작합니다. 먼저 작은 원을 그리며 모든 방향으로 걸어보세요.
2. 모닥불 앞쪽의 `30 stud`, `60 stud`, `90 stud`, `120 stud` 깃발을 따라 걸으세요. 잠깐 뒤를 보며 기지가 지평선 뒤로 내려가는지 확인합니다. 거리 표시는 **구면을 따라 잰 거리**이며 깃발은 길 옆에 약 5 stud 비켜 있습니다.
3. `30° → 60° → 90° → … → 180° → … → 360°` 표지의 대원 코스를 이어서 따라갑니다. 길에서 조금 옆으로 비켜도 공 표면은 모든 방향으로 이어집니다.
4. 반대편 `180°`에서도 걷고, 멈추고, 점프합니다. 발 아래 방향으로 다시 내려와야 합니다.
5. 약 **63초** 동안 직진하면 한 바퀴입니다. 실제 시간은 곡선 이동·장애물·가속 때문에 늘어납니다. 카메라를 돌리지 않고 코스를 유지한 뒤 모닥불로 돌아오는지 확인하세요.
6. 괴물은 기지에서 약 377 stud 떨어진 표면에서 14 stud 앞까지 다가갔다가 돌아갑니다. 왕복 약 **104초**입니다. 60~120 stud 깃발에서 괴물이 오는 방향을 바라보고 머리부터 나타나는지 확인합니다.

## 3. 카메라·경사진 물체

기지 옆 기울어진 회색 바위를 찾으세요. 옆면에 걸어가고, 위로 점프하고, 옆으로 빠져나와 보세요. 바위는 이동을 막을 수 있지만 **몸의 위쪽과 중력은 항상 행성 중심 기준**이어야 합니다. 옆면에 붙어 몸이 벽 쪽으로 눕는 것은 오류입니다. 작은 충돌 구체를 쓰므로 높은 턱은 점프가 필요할 수 있습니다.

행성의 위·옆·아래에서 카메라를 좌우로 돌려 보세요. 기존 월드의 위쪽 축을 넘는다고 갑자기 180도 뒤집히면 안 됩니다. 나무·바위가 카메라 사이에 끼면 카메라가 가까워졌다가 다시 멀어집니다. 점프 후 착지할 때 떨림이나 급회전이 생기는지도 적어 주세요.

## 4. 휴대폰 에뮬레이터

Studio의 **Device Emulator(기기 에뮬레이터)**에서 휴대폰을 선택하고 Play 하세요. 메뉴 위치는 Studio 버전에 따라 다를 수 있습니다. 조이스틱과 점프 버튼이 보이는지 확인하고, **이동하면서 오른손으로 카메라 회전**, **이동하면서 점프**를 각각 해보세요. 세로·가로 화면에서 낮/밤 버튼이 조작을 가리지 않는지도 확인합니다. 에뮬레이터 성공만으로 실제 휴대폰 성능까지 확인한 것은 아닙니다.

## 5. 2인 테스트

1. Studio의 **Server & Clients(서버 및 클라이언트)** 테스트에서 플레이어 수를 **2**로 시작합니다.
2. 첫 번째 접속자는 기지, 두 번째 접속자는 반대편에서 시작합니다. 접속 순서는 창 번호와 다를 수 있습니다. Output에 `PlanetTest spawn … base/opposite`가 표시됩니다.
3. 두 창 모두 걸을 수 있고, 서로의 위치·회전이 서버에 전달되는지 확인합니다.
4. **불투명한 행성이 가리므로 반대편 사람을 땅 너머로 볼 수는 없습니다.** 서버 창의 자유 카메라로 행성 밖에서 두 캐릭터를 살펴보세요. Explorer에서 각 플레이어 모델을 선택하고 F로 초점을 맞춘 뒤 밖으로 이동하면 자세를 비교하기 쉽습니다. 같은 월드 기준으로 반대편 캐릭터의 머리 방향이 반대여야 합니다.
5. 플레이어 둘을 90° 표지 근처로 이동시켜 만납니다. 상대가 움직이고 점프하는 모습이 자연스럽게 보이는지 검사하세요.
6. 한 명만 Reset하고, 다른 플레이어의 조작과 괴물 이동이 유지되는지 확인합니다.
7. `OppositeSpawns = false`로 바꾸면 모두 기지에서 시작하므로 같은 장소에서 비교하기 쉽습니다.

낮/밤 버튼은 **누른 플레이어의 화면만** 바꿉니다. 이 시험에서는 동기화하지 않습니다. 밤에는 기지 밖이 매우 어둡습니다. 행성 반대편에서는 불빛이 행성에 가려 안 보이는 것이 정상입니다.

## 체크리스트

- [ ] 모닥불 근처에서 준비 후 땅 위에 착지한다.
- [ ] 모든 방향으로 걷고 한 바퀴 돌아 기지로 온다.
- [ ] 행성 위·옆·아래에서 점프하고 바깥으로 튕겨 나가지 않는다.
- [ ] 카메라가 특정 지점에서 갑자기 뒤집히거나 계속 떨리지 않는다.
- [ ] 바위 옆면에 닿아도 중력 기준이 바뀌지 않는다.
- [ ] 나무·바위·깃발이 행성 바깥 방향으로 서 있고 떠 있지 않다.
- [ ] 괴물이 표면을 따라 2회 이상 왕복한다.
- [ ] 모바일에서 이동·점프·카메라를 함께 쓸 수 있다.
- [ ] 두 플레이어의 자세와 이동이 서로/서버에서 확인된다.
- [ ] Reset 후 카메라·조작·점프가 정상이다.
- [ ] 낮/밤 전환이 되고 Output에 빨간 오류가 없다.

## 숫자 바꾸기

**Stop**을 누르고 Explorer에서 **ReplicatedStorage → Shared → Config**를 엽니다. 맨 위 설정 표에서 숫자를 바꾸고 다시 Play 합니다. Play 중 변경은 Stop 때 사라질 수 있습니다. 원하는 결과는 Ctrl+S로 저장하세요.

| 설정 | 시작값 | 뜻 |
|---|---:|---|
| Radius | 160 | 행성 반지름 |
| WalkSpeed | 16 | 걷는 속도 |
| Gravity | 90 | 중심으로 당기는 힘. 클수록 빨리 내려옴 |
| JumpSpeed | 38 | 바깥쪽 점프 시작 속도 |
| CameraDistance | 12 | 기본 카메라 거리 |
| CameraSensitivity | 0.004 | PC·터치 카메라 회전 감도 |
| CameraPitch | 12 | 기본 카메라의 내려다보는 각도 |
| TreeCount / RockCount | 48 / 12 | 배치 후보 수. 길·기지 주변을 비워 실제 나무는 기본 43그루 |
| Embed | 0.4 | 물건 밑을 표면에 묻는 깊이 |
| OppositeSpawns | true | 짝수 번째 접속자를 반대편에 스폰 |
| MonsterSpeed | 7 | 괴물 표면 이동 속도 |
| MonsterFarFraction | 0.75 | 반 바퀴 길이에 대한 출발 거리 비율 |
| CenterX / CenterY / CenterZ | 0 / 0 / 0 | 행성 중심 위치 |

먼저 **Radius 160**(약 63초), 그다음 **220**(약 86초), **280**(약 110초)을 비교해 보세요. 작은 행성일수록 지평선이 빨리 가리고 곡률이 강해집니다. 한 바퀴 예상 시간은 `2 × π × Radius ÷ WalkSpeed`입니다. 반지름 범위는 40~900으로 제한했습니다. 중심 높이는 우선 0으로 두세요. 파일에 저장된 낙사 삭제 높이는 -50,000입니다.

지형은 가로·세로·높이가 같은 Ball 파트 하나로 만든 완전한 구입니다. 가까운 발밑만 보면 평평하게 느껴질 수 있습니다. Play 중 서버 화면의 Explorer에서 `Workspace → PlanetTest → Planet`을 선택하고 F로 초점을 맞춘 뒤 줌아웃하면 전체 공 모양을 확인할 수 있습니다.

다른 항목은 최초 시험에서는 그대로 두는 것이 좋습니다. `MoveResponse`, `OrientationResponse`는 조작 반응과 몸 회전에 관계되므로 떨림 보고를 받은 뒤 조절할 수 있습니다.

## 숲 키트 사용(선택)

기본 파일은 간단한 파트 나무·바위로 실행됩니다. 실제 파일 위치는 저장소의 `wildhold/assets/env/EnvModels.fbx`입니다. 원본 파일은 변경하지 않습니다.

Studio의 3D Importer로 FBX를 가져와, `Spruce1` 같은 나무와 `Boulder1` 같은 바위의 **Model 또는 MeshPart**를 **ReplicatedStorage.EnvModels** 안에 넣으세요. 중간 폴더가 있어도 찾습니다. 나무 하나의 Model 안에 여러 MeshPart를 넣는 것도 가능합니다. `Spruce` / `Boulder`로 시작하는 이름을 유지하고, 원본 모델은 로컬 Y축이 위를 향하게 준비하세요. 모델 밑면을 기준으로 구면에 세웁니다.

메시 업로드/사용 권한과 실제 충돌 형상은 Studio에서 확인해야 합니다. FBX를 XML에 직접 넣어 자동 업로드하지는 않았습니다. Studio에서 임포트한 파일은 별도로 저장해 보관하세요. Python 재빌드는 수동 임포트한 메시를 포함하지 않습니다.

## 소스 재빌드와 검사

저장소 루트에서 Python 3와 Luau CLI로 실행합니다.

```sh
python planettest/tools/build_place.py
python planettest/tests/run.py --luau luau --compiler luau-compile
```

소스 설정 파일은 `planettest/src/shared/Config.lua`입니다. 기존 `wildhold/tools/build_place.py`의 XML 포장 도구와 `wildhold/tests`의 모의 자료형·API 검사기를 **읽기 전용**으로 재사용합니다. 생성 파일에는 WILDHOLD 게임 코드를 넣지 않습니다.

검사한 항목:

- XML 구조·소스 일치·라이선스 포함 및 Luau 소스 8개 문법 검사.
- 실제 ClientMain을 먼저 실행하고 폴더/모듈을 뒤늦게 전달하는 시작 순서 회귀 검사. 외형 로딩이 끝나지 않아도 제한 시간 뒤 스폰 준비를 마치는 검사.
- 기본 파트/임포트 모형 양쪽 배치의 밑면 거리와 바깥쪽 방향.
- 행성 중심을 옮긴 경우 포함, 한 바퀴 3,600개 시점의 좌표와 방향 운반.
- 시나리오마다 괴물 12,000개 시점의 표면 거리·속도와 실제 서버 애니메이션 코드.
- R15/R6의 기지·반대편 스폰, 준비 완료 후 물리 소유권 전달 코드.
- 실제 조종기 코드의 6방향 힘 계산, 반대편 점프, 벽면에서 점프 금지.
- 실제 카메라 코드 1,800프레임, 장애물 모의 응답, 터치 영역 분리, 조종기 정리.

**모의 엔진은 물리 적분·충돌 해결·네트워크 지연·렌더링·진짜 애니메이션 로딩을 재현하지 않습니다.** 위 검사 통과는 Studio에서의 자연스러운 조작을 보장하지 않습니다. 실제 FBX는 불러오지 않았고, 임포트 검사는 이름·크기를 가진 모의 MeshPart로 했습니다.

## 이상하면 보내줄 정보

다음 양식을 복사해서 알려주세요. 모든 항목을 채우지 못해도 괜찮습니다.

```text
기기/테스트: PC / 휴대폰 에뮬레이터(기종·가로/세로) / 실제 휴대폰 / 2인
아바타: R15 또는 R6 (모르면 스크린샷)
바꾼 Config 숫자:
위치: 기지 / 90° / 180° / 바위 옆 / 기타
한 행동: 예) W로 걷다가 Space, 오른쪽으로 카메라 회전
기대한 모습:
실제 모습:
재현: 매번 / 가끔, Reset 뒤에도 같은지
Output 빨간 줄: 첫 오류부터 줄 번호와 아래 호출 경로까지 복사
스크린샷 또는 5~10초 영상: 발·행성·카메라 방향이 함께 보이게
2인이라면: 어느 창에서 보이고, 상대 창에서는 어떻게 보이는지
```

`PlanetTest recovery: 행성 이탈`이라는 노란 줄은 관통/튕김을 감지해 재시작한 기록입니다. 이것도 함께 보내 주세요. 시작 후 계속 공중에 멈춰 있다면 준비가 끝나지 않은 것이므로 Output과 화면을 보내 주세요.
