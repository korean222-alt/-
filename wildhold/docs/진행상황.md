## 1. 게임 한 줄

약한 펫을 잡아 팀을 꾸리고, 더 강한 야생 펫을 약화·포획한다. 밤에는 그 펫 팀과 방어 시설로 기지(Core)를 지키는 **협동 생존** 게임 (Roblox, Luau).
원래 기획서: `WILDHOLD_Game_Design_v4_Pet_Centered.md` (사용자가 가지고 있음). 외부 에셋 조사 문서: `WILDHOLD_Asset_Research_and_Pet_Production.md`.

## 2. 사용자와 정한 방향 (확정)

| 항목 | 결정 |
|---|---|
| 분위기 | **99 Nights in the Forest 같은 생존 톤.** 낮은 평범하게 밝은 숲(탐험·포획 시간), 밤은 짙은 안개와 어둠, 기지 불빛만 안전, 괴물은 빛나는 눈부터 보임. **낮과 밤이 계속 바뀌므로 낮·밤 대비가 긴장감의 핵심** (사용자 확인). 아이들도 하는 게임이라 잔인한 표현은 없음 |
| 펫 디자인 | **쎄 보이는 펫 (ARK·포켓몬 느낌, 단 사실적 X, 만화풍인데 사나운 스타일).** 성장형 추천: 잡을 때는 새끼, 키우면 사나운 성체 |
| 펫 제작 방법 | **Meshy AI** (그림 → 3D → 네 발 자동 리깅 → 걷기/대기 동작). 무료 플랜(월 100크레딧, CC BY 4.0 = 출처 표기 시 상업 가능)으로 시작, 필요하면 Pro 한 달($20)만 결제. 공격·기절 등 부족한 동작은 코드 애니메이션으로 보완 |
| 예산 | 최대한 무료, 어쩔 수 없으면 최소 비용. 재미가 검증되기 전에는 올인하지 않음 |
| 사용자 수준 | Roblox/3D 초보자. 설명은 쉬운 한국어, 할 일은 체크리스트로 |

## 3. 지금까지 한 일

### 3.1 1~8단계 다시 만들기 (완료)
- GPT 가 만든 원본(회색 판자 + 떠 있는 글씨)의 **서버 로직은 유지**하고 보이는 것 전부를 새로 만들었다.
  (포획 → 우리 등록 → 밤 생존 → 영구 확정, DataStore 세션 잠금 저장, 서버 권한형)
- 맵: 지형, 말뚝 울타리 기지, 3 길목 + 괴물 굴, 연못, 알파의 숲, 자원 노드 모델, 레벨별 방어 시설 모델
- 크리처: 서버는 보이지 않는 기준 파트만 움직이고 클라이언트가 모델을 붙여 절차적 애니메이션
- 효과: 속성별 공격, 포획 바구니 3회 흔들림, 건설 먼지, 괴물 연기, 드랍 자원 둥실
- UI: 낮/밤 알약 + 타이머 + Core 체력, 목표 카드, 출전 펫 3칸(3D 얼굴), 배너, 결과 화면, 펫 패널 재디자인
- 버그 수정: 포탑이 앞 벽에 시야가 막혀 벽을 치는 적을 못 쏘던 문제

### 3.2 블렌더 펫 4종 (완료, 단 "새끼/귀여움" 톤)
- `wildhold/blender/` 파이썬 스크립트로 SDF 조각 → 텍스처 베이크 → 리깅 → FBX
- 모슬링, 엠버펍, 셸버브, 브라이어혼 α. 삼각형 7~10k, 뼈 10~12개
- 사용자 피드백: 너무 귀엽다. **성장형의 새끼 단계로 두고, 성체는 Meshy 로 사나운 디자인을 새로 만든다**

### 3.3 생존 톤 전환 (이번 채팅 마지막 작업)
- `EnvironmentController`: 평범하게 밝은 낮 / 붉은 노을 / 짙은 안개 밤(가시거리 짧음, 채도 낮춤) / 새벽. 노을·밤에 모든 캐릭터에 등불, 횃불·모닥불 깜빡임
- 지형 색 어둡게, 숲 경계를 키 큰 전나무 두 줄로, 안쪽에 죽은 나무·쓰러진 통나무·빛나는 버섯 (꽃 제거)
- Core: 제단 위 **성스러운 모닥불**(밤에 기지를 비추는 큰 불빛) + 그 위에 떠 있는 수정
- 괴물 몸을 더 어둡게, 눈을 더 크게 (안개 속에서 눈부터 보이게)
- 검증: `selene src` 오류 0 (기존 경고 3개), `./tests/run.sh` **모든 검사 통과**, `WILDHOLD.rbxlx` 재생성 완료
- 맵 미리보기 렌더: `render_scene.py` 에서 월드 안개를 빼서 (CPU 로 10분 넘게 걸렸음) 3장 모두 약 4분씩에 렌더됨.
  남은 일: `run_game.luau` 의 장면 내보내기가 **테스트용 가짜 블렌더 펫(MeshPart)을 회색 상자로** 내보내서 초원 사진에 상자가 보인다.
  내보내기에서 `MeshPart` 를 빼고 → `./tests/run.sh` → `render_scene.py docs/images` 로 README 사진 3장 교체 (게임 버그 아님)

## 4. 코드 구조 (핵심만)

```text
wildhold/
├── WILDHOLD.rbxlx            # tools/build_place.py 로 src 에서 생성 (Studio 에서 여는 파일)
├── src/shared/Config/        # 모든 수치 (PetConfig: 종·키·스폰, MapConfig: 배치, AudioConfig: 소리 ID)
├── src/shared/Visuals/       # Build(파트 도우미), Props(나무·바위·버섯…), Structures(기지·방어시설·Core), Creatures(대체 펫·괴물)
├── src/server/Services/      # 게임 로직. MapService 가 맵 생성
├── src/client/Controllers/   # CreatureController(크리처 표시), Rig(뼈/파트 리그), Anim(절차적 포즈),
│                             # FXController, EnvironmentController(조명), UIController(HUD), PetController(패널), WorldUI, Audio, Portrait
├── assets/pets/              # 블렌더 펫 FBX / png / blend
├── blender/                  # 펫 생성 스크립트 (bpy 4.2)
└── tests/                    # 헤드리스 플레이 테스트 (Luau VM + Roblox API 모의)
```

**펫 모델 연결 규칙 (Meshy 모델을 넣을 때 중요)**
- Studio 에서 가져온 모델을 `ReplicatedStorage/PetModels/<종ID>` 에 넣으면 `CreatureController` → `Rig.fromMesh` 가 사용한다. 없으면 `Creatures.lua` 파트 대체 모델
- 크기: `PetConfig.Heights[종]` 으로 자동 맞춤. 앞 방향: `Front` 또는 `Head` 뼈와 `Body` 뼈 위치로 자동 판별
- 애니메이션: `Anim.lua` 가 **뼈 이름**(Body, Head, Neck, EarL/R, Tail/Tail1/Tail2, LegFL/FR/BL/BR …)에 포즈를 준다
- **Meshy 리그는 뼈 이름이 다를 것** → 다음 작업에서 이름 매핑 표나 AnimationController 클립 재생을 추가해야 한다 (6장)

## 5. 개발 환경 다시 세우기 (새 컨테이너일 때)

```bash
pip install bpy==4.2.0 scikit-image          # 블렌더 파이썬 (펫 빌드, 맵 미리보기 렌더)
cargo install selene --locked                # Luau 린트 (설정: wildhold/selene.toml + roblox_min.yml)
cd wildhold/tests/luaurun && cargo build --release && cp target/release/luaurun ~/.cargo/bin/   # Luau VM
cd wildhold && python3 tools/build_place.py  # rbxlx 만들기
./tests/run.sh                               # 한 판 헤드리스 테스트 (끝나면 "모든 검사 통과")
python3 tests/render_scene.py docs/images    # 테스트가 내보낸 맵을 Blender 로 렌더
```
- `tests/api.lua` 는 `npm pack @rbxts/types` 후 `tests/gen_api.py` 로 다시 만들 수 있다
- 이 환경에서 `meshy.ai` 는 네트워크로 막혀 있다. Higgsfield 커넥터는 연결돼 있지만 크레딧 0.19 (무료) 이고, 그쪽 자동 리깅은 사람형 전용

## 6. 다음 작업 (우선순위)

0. 사용자의 Studio 확인 결과 반영 (밤 밝기·안개 농도는 `EnvironmentController` 의 `LOOKS` 숫자만 조절). README 맵 사진 교체 (3.3 의 "남은 일", 10분 정도)
1. **Meshy 성체 펫 1마리 통합** (사용자가 Meshy 결과물을 가져오면)
   - 받은 FBX/GLB 를 Blender 에서 점검: 삼각형 ≤ 10k, 텍스처 1장, 원점 발밑, 스케일
   - 뼈 이름을 우리 규칙으로 매핑하거나 `Rig.lua` 에 매핑 표 추가. Meshy 동작 클립(대기/걷기)을 Roblox 애니메이션으로 가져와 `AnimationController` 로 재생, 공격·기절은 기존 절차적 포즈로 덧입히기
   - 테스트 하네스에 해당 뼈 구조 가짜 모델 추가해서 검증
2. **성장형 데이터**: `PetConfig` 에 `Stage`(새끼/성체)와 진화 조건(레벨), 종별 모델 ID 분리. 저장 데이터 `Version` 올리고 마이그레이션
3. **알파 브라이어혼 다시 디자인** (위협적인 보스급) — Meshy 로 제작
4. 생존 게임플레이 보강 후보 (사용자와 상의 후): 밤에 기지 불빛 밖에 오래 있으면 불리해지는 규칙, 횃불/등불 아이템, 밤 괴물 추가 디자인
5. 효과음 ID 연결 (사용자가 업로드하면 `AudioConfig` 에 넣기)
6. Studio 실검증 결과 반영 (아직 **실제 Studio 실행은 한 번도 확인 못 함**)
