# 졸졸 동물 기차 (Roblox 게임)

## 게임 한 줄 설명
맵에 돌아다니는 아기 동물에 닿으면 플레이어 뒤에 줄지어 따라오고, 동물들을 농장에 데려다주면 별을 받아 새로운 섬을 여는 게임.

## 대상과 핵심 원칙
- 대상: 6~12세 아이. 글을 잘 읽지 않는다고 가정한다.
- 접속 후 10초 안에 첫 동물을 모을 수 있어야 한다. 시작 메뉴, 캐릭터 선택, 긴 튜토리얼 창은 만들지 않는다.
- 조작은 로블록스 기본 조작(걷기, 점프)만 사용한다. 새 키나 버튼을 배워야 하는 기능은 만들지 않는다.
- 안내는 글자보다 그림, 화살표, 반짝임, 소리로 한다. 글자가 필요하면 아주 짧게(3단어 이내) 쓴다.
- 혼자 플레이해도 재미있어야 한다. 다른 플레이어가 있어야만 되는 기능은 넣지 않는다.
- 실패해도 잃는 것이 거의 없어야 한다. 모은 별, 열린 섬, 도감은 절대 사라지지 않는다.
- 폭력적인 표현, 무서운 연출은 넣지 않는다. 밝고 귀여운 분위기를 유지한다.

## 기술 규칙
- 언어는 Luau. 가능하면 타입 주석(`--!strict`)을 사용한다.
- Roblox Studio MCP 도구로 Studio에 직접 파트와 스크립트를 만든다.
- 별, 동물 소유, 배달 성공, 섬 해금은 반드시 서버(ServerScriptService)에서 결정한다. 클라이언트는 화면 표시와 입력만 담당한다.
- 서버와 클라이언트 통신은 ReplicatedStorage/Remotes 폴더의 RemoteEvent로만 한다. 서버는 클라이언트가 보낸 값을 믿지 말고 다시 확인한다.
- 공용 설정값(속도, 별 보상, 섬 해금 비용 등)은 ReplicatedStorage/Shared/Config 모듈 한 곳에 모은다.
- 스크립트 이름은 역할이 드러나게 짓는다 (예: AnimalService, FarmService, DataService).
- 툴박스 무료 모델은 사용하지 않는다(악성 스크립트 위험). 모델은 파트를 조합해 직접 만든다.
- 휴대폰과 태블릿으로 하는 아이가 많으므로 UI는 크게, 화면 가장자리의 안전 영역을 피해서 배치한다.

## 작업 방식
- 한 번에 기능 하나만 만든다. 요청하지 않은 기능은 추가하지 않는다.
- 만들기 전에 무엇을 어디에 만들지 짧게 계획을 말한다.
- 만든 후에는 플레이 모드로 직접 테스트하고, 출력 창 오류가 없는지 확인한다.
- 작업이 끝나면 만든 스크립트의 사본을 이 폴더의 `src/` 아래에 같은 이름의 `.luau` 파일로 저장한다 (백업용).
- 작업 끝에 "무엇을 만들었는지 / 어떻게 테스트했는지 / 내가 Studio에서 직접 확인할 것"을 3줄로 알려 준다.
